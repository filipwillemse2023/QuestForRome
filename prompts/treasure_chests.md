# description
We will now introduce the concept of items that can contain other items. Basically, we should be able to define an item type "item container" and apply that to any item definition (so we can for example create treasure chests, vases, cupboards, whatever that can contain items) and in that case we should be able to define an optional animation for the empty status (if not defined, the animation will remain the default one even when the container is empty, but for example for treasure chests, we can then define a sprite of an open chest). 
When items of this type are placed on the map, we should be able to select them on the map and then define the contents of the container. This is an item from the normal item list (with the exception of container items, we cannot put a container inside another container) or a weapon. A container item will also behave like a solid tile, i.e. the hitbox will block the player. When the player presses the A button near this hitbox (range of 6 pixels around the hitbox on all sides), he will open the container (this will change the sprite to the open animation/sprite) and the player will receive the items inside (they will just trigger the functions of those items as if the player would have picked up said item in the overworld). An extra movement type will be added to the player for this as well (called "item pickup") that will be player on opening the chest and the item or weapon sprite will be shown just above the player character. The animation will last for a fixed amount of 4 seconds during which the game is paused, after that the player goes back to the normal standing still animation and the item/weapon sprite above the head disappears and the game continues. The container is then empty and will remain empty for the rest of the game.
