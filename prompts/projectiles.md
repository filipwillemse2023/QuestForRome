# description
There should be a new category of objects, named projectiles, that are basically the description of projectiles that can be fired either by the player or by enemies. Animations can be defined for the start (i.e. shown immediately after appearing), during flight and at impact. The first and last are optional, if no animations are defined for those movement parts, the projectile immediately starts in flight animation and just ends at impact. A hitbox also needs to be added to the projectile. Also, the projectile will have a movement type (to be selected from a predefined list determined by the game engine, will specify later which types to be added for starters), a speed (tiles per s, decimal value), a checkbox to indicate if the projectile moves through solid surfaces and a base damage value.
The following movement types will be available:
- fixed function: a fixed function for movement will be defined as y = a * x for which a can be defined, it is a decimal value and y and x are the x and y coordinate changes. The speed in tiles per second determines the change in x per frame and y can then be calculated based on the function definition.
- track player: the projectile will adjust its movement each frame to get closer to the player character location according to the defined speed

Projectiles always keep moving until they either hit a solid tile (unless move through solid surface is on), gets off the screen, or hits the player (in that case, the player gets hit and loses health based on the damage value). If the bullet hits something en stops there (solid or player) and an impact animation is present, that gets played and then the projectile disappears, if no animation is defined the projectile simply disappears (and the projectile object gets destroyed).
